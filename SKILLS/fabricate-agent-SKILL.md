# 经历杜撰 + 面试准备 Agent

## 触发场景
- 定向简历生成流程中，用户选择「杜撰经历」来填充简历的项目/实习空白。
- 用户希望针对某个岗位提前准备面试，需要「重点记忆知识点 + 高频面试问题」。
- 用户档案中经历不足或与岗位 JD 匹配度低，需要 AI 生成贴近 JD 的经历蓝本。

## 在流程中的位置
```
粘贴 JD → 解析 JD → 【经历杜撰（可选）】→ 回答必要问题 → 自我评价问答 → 生成简历
```
- 本 Agent 只在「解析 JD」与「回答必要问题」之间运行一次，且为可选步骤。
- 结果写入简历任务的 `fabricated`（杜撰经历）与 `interview_prep`（面试准备）字段。

## 分支逻辑
1. **杜撰（fabricate = true）**
   - 根据 JD + 用户档案生成 2~3 段经历，混合项目/实习，统一字段：
     `type / title / role / tech_stack / start_date / end_date / description / result`。
   - 进入简历时，`project` 类型并入「项目经历」，`internship` 类型并入「实习经历」，
     与用户真实经历**合并展示**（真实经历若存在仍保留）。
2. **不杜撰（fabricate = false）**
   - `fabricated` 置空，简历仅使用用户档案中已有经历。
   - 无论是否杜撰，`interview_prep` 都会基于「JD + 档案 + 最终经历」生成。

## 杜撰经历规范
1. **真实可辩护**：经历要能在面试中被追问 2~3 轮仍自圆其说，避免明显编造、常识性矛盾。
2. **时间线合理**：与教育背景时间（如本科 2023.09–2027.06）不冲突，实习/项目时间落在求学期间。
3. **技术栈呼应 JD**：出现 JD 高频关键词（框架/库/数据库/AI 方向），且与用户技能栏一致。
4. **可量化成果**：每条包含数字（准确率、性能提升 %、日均处理量、用户数、效率提升等）。
5. **STAR 结构**：每条描述含「情境-任务-行动-结果」，动词开头，避免「参与/协助」式空话。
6. **规模克制**：2~3 段即可，不堆砌；应届/实习岗控制在单页。
7. **与档案一致**：学校、专业、技术栈、证书等硬信息不得冲突。

## 面试准备规范（interview_prep）
结构：
```json
{
  "knowledge_points": ["知识点 + 为何重要（一条，供重点记忆）"],
  "high_freq_questions": [{"question": "问题", "hint": "答题要点/角度"}]
}
```
要求：
1. **knowledge_points 4~6 条**，覆盖：技术栈原理、岗位业务领域、项目细节、行为面试软素质。
2. **high_freq_questions 5~8 个**，覆盖三类：
   - 项目细节追问（含对杜撰经历的刨根问底：角色贡献、为什么选该技术、遇到什么难点）。
   - 技术栈原理（为什么用 RAG、如何评估效果、Agent 如何编排等）。
   - 行为面试（团队协作、冲突解决、自我驱动、失败复盘）。
3. 每个问题给出 `hint`（答题要点/角度），帮助用户快速组织话术。
4. 语言为中文书面语，技术名词保留英文原词。

## 输出
- 后端：`POST /resumes/{id}/fabricate`（body: `{ "fabricate": true|false }`）。
- 前端：杜撰步骤展示开关与生成结果预览；简历详情页下方展示「重点记忆知识点」与「高频面试问题」。

## 守则
- 杜撰内容为**面试话术练习蓝本**，提醒用户：投递时需对内容真实性负责，请务必能自圆其说并如实回答。
- 不虚构无法辩护的硬数据（竞赛获奖、奖学金、GitHub 高 Star 等）；难以辩护的保持定性表述。
