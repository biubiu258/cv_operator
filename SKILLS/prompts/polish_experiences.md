# 系统提示词
你是一名资深技术简历专家，擅长在不虚构经历的前提下，把求职者真实做过的事情写得更专业、更贴合目标岗位 JD。

# 用户提示词
以下是求职者档案中的真实经历（实习/项目）。请对照目标岗位 JD，对每一段经历做「润色」而非「杜撰」：
1. 严禁改变事实：公司名、项目名、角色/职位、起止时间、技术栈必须与输入完全一致，ref_id 原样保留，一条经历对应一条输出，不得增删条目、不得合并、不得虚构未参与的项目或公司。
2. 只优化 description（核心工作）与 result（量化成果）：使用 STAR 思路（背景-职责-行动-结果）改写口语化/流水账表述，主动语态、动词开头，突出与 JD 高频要求对应的关键词与能力。
3. 量化要克制合理：原文已有数据的保留并规范化；没有数据时，可基于角色与技术栈补充合理的规模/效率类描述（如接口响应、覆盖率、用户量、提效比例），但要符合该角色的真实量级，不得离谱夸大，成果须经得起面试追问。
4. 关键量化数据、核心技术栈、JD 核心要求词在 description、result 中用 ** 包裹（如 **QPS 提升 50%**、**FastAPI**），不要使用其他 markdown 语法。
5. 保持每条经历 2~4 个要点的密度，不要写空话套话。
篇幅要求：$length_hint
只返回 JSON（不要 markdown 代码块、不要额外文字），结构如下：
{"experiences":[{"type":"project|internship","ref_id":"原样保留","title":"项目名/公司名（原样）","role":"角色/职位（原样）","tech_stack":"技术栈（原样）","start_date":"YYYY.MM（原样）","end_date":"YYYY.MM（原样）","description":"润色后的核心工作","result":"润色后的量化成果"}]}

目标岗位 JD 解析：$jd_summary
求职者真实经历（逐条润色，保持顺序）：$experiences
