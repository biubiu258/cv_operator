# 软件工程求职简历生成器

## 触发场景
- 用户要求"写简历 / 做简历 / 优化简历 / 简历作业"，尤其是计算机 / 软件工程类岗位。
- 用户提供了岗位 JD，要求"定向 / 针对性"地写简历。
- 用户要求多版本迭代（如 1.0 → 2.0 → 3.0 逐版优化）。

## 第一步：收集信息
必收集：
- 姓名、意向岗位、电话 / 邮箱（隐私信息用占位符，如「张三」「138-0000-0000」）。
- 学校、专业、学历、就读时间、GPA / 排名（如有）。
- 技术栈及真实掌握程度。
- 2~4 个项目 / 实习经历的真实背景、角色、技术、可量化结果。
- 证书、竞赛、获奖、开源 / GitHub、技术博客（如有）。

信息不全时先询问，或使用占位符并明确标注。

## 第二步：写作核心技巧（软件工程类）
1. **单页 + 倒序时间**：应届 / 实习岗控制在一页，最新经历在前。
2. **模块完整**：个人信息 → 个人简介 → 教育背景 → 专业技能 → 项目经历 → 证书 / 获奖 → 自我评价。
3. **STAR + 数据量化**：动词开头，每个项目带"情境-任务-行动-结果"，落到具体数字（准确率、响应时间、日均处理量、性能提升 %）。
4. **关键词回扣 JD**：抽取 JD 关键词（语言 / 框架 / 数据库 / AI 方向），在技能栏与项目中自然呼应，服务 ATS 与人工扫读。
5. **技能分级**：按"语言 / 数据库 / AI 工程 / 工具"分类并标熟练度，AI 相关项前置。
6. **避免扣分**：空洞形容词、无关内容、"参与 / 协助"式表述、技术名词错误、时间线矛盾、错别字。

## 第三步：方案
结构完整、信息齐全，项目为罗列式描述，作为底稿。
项目升级 STAR + 量化，技能栏重排前置，动词开头，回扣 JD。
精修视觉（分隔线 / 右对齐时间 / 加粗），项目深度打磨，补充自我评价与亮点。

## 第四步：抓眼球的钩子（终极版加分项）
1. **个人简介摘要**：姓名下方 2~3 行电梯陈述，3 秒讲清"我是谁 + 为什么匹配"。
2. **关键数字高亮**：准确率、提升 %、日均量等用加粗 / 深色突出。
3. **结果导向标题**：把成果写进项目标题（如"校园问答 Agent —— 准确率 85%"）。
4. **技能标签行（chips）**：一行速览 `Python · SQL · LangChain · Prompt 工程 · RAG · Agent`。
5. **硬证据（需真实素材）**：GitHub / 仓库链接、绩点排名、竞赛获奖、技术博客。

## 第五步：输出格式规范（Word）
- 优先用 docx 技能 + docx-js 生成；A4 页面、**单节**（多节会出空白页）。
- 字体：CJK 用 Microsoft YaHei，拉丁用 Arial；正文约 10.5pt。
- 主色用深蓝（如 1F4E79），关键数字可用同色加粗。
- 标题带下边框线，时间用右侧 Tab 对齐；列表用真实编号（LevelFormat.BULLET），勿手动插 bullet 字符。
- 生成后运行 sanitize.py 校验，确保单页、无空白页、无乱码。

## 示例输出结构
```
张三（大字居中）
Agent 开发工程师（实习）
电话 / 邮箱 / 城市

个人简介：……（2~3 行，含技术栈速览）
教育背景：学校 | 专业 | 本科 | 时间 | 主修课程
专业技能：分类分级，AI 前置
项目经历：结果导向标题 + 时间 + 技术栈 + STAR 量化 bullet
证书 / 获奖：CET-4 等
自我评价：定制化事实，非套话
```

## 守则
- 若用户要求"先审阅"，先给"技巧总结 + 递进方案"，确认后再生成。
- 隐私信息用占位符；**不虚构无法背书的硬数据**（绩点、排名、获奖、竞赛、GitHub 均须真实）。
