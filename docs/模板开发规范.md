# 简历模板开发规范

本文档面向「简历模板」开发者，说明如何新增一套 docx 版式、渲染函数需要支持哪些参数、可复用哪些工具函数，以及需要遵守的版式约定。

## 1. 模板在哪里登记

模板统一登记在 `backend/app/services/resume_generator.py` 的 `TEMPLATES` 注册表：

```python
TEMPLATES = {
    "classic": {"label": "简洁单栏", "render": _render_classic},
    "split":  {"label": "双栏",     "render": _render_split},
}
```

- `key`：模板唯一标识（字符串），会持久化到 `Resume.template`，前端选择器与路由校验都以此为准。
- `label`：前端展示名称。
- `render`：渲染函数（见下）。

新增一个模板只需：实现渲染函数 + 在 `TEMPLATES` 加一条，无需改动路由与前端。

## 2. 渲染函数签名（必须支持）

所有渲染函数必须使用如下统一签名：

```python
def _render_xxx(
    user,
    jd_summary,
    personal_summary,
    self_evaluation,
    out_dir: Path,
    target_position: str = "",
    sections=None,
    fabricated=None,
    skills_curated=None,
    expected_salary: str = "",
    include_salary: bool = True,
    length: str = "fresh",
    custom_pages: int = None,
) -> str:
    ...
```

返回值：生成的 `.docx` 文件路径（字符串）。建议直接复用 `_save_docx(doc, user, out_dir)` 完成保存。

### 参数说明

| 参数 | 类型 | 说明 |
| --- | --- | --- |
| `user` | 对象（duck-typed） | 用户信息，字段见 §3 |
| `jd_summary` | dict | JD 解析结果，键：`position` / `tech` / `soft` / `domain` / `requirements` |
| `personal_summary` | str | 个人简介正文（可能含 `**重点**` 标记） |
| `self_evaluation` | str | 自我评价正文（可能含 `**重点**` 标记） |
| `out_dir` | Path | 输出目录路径 |
| `target_position` | str | 定向简历填写的意向岗位（优先级已由上层处理，可直接使用，空则回退） |
| `sections` | list[str] \| None | 用户勾选要包含的模块；为空/`None` 表示包含全部模块 |
| `fabricated` | list[dict] \| None | 杜撰经历蓝本，字段见 §4 |
| `skills_curated` | list \| None | AI 精选技能；元素为 `{"name": str, "proficiency": str}` 或带 `.name` / `.proficiency` 的对象 |
| `expected_salary` | str | 期望薪资（可能为「面议」） |
| `include_salary` | bool | 是否在简历中展示期望薪资 |
| `length` | str | 篇幅选项：`fresh`（应届/一页）/`junior`（1-5年/两页内）/`senior`（5年+/三页内）/`custom`（自定义） |
| `custom_pages` | int \| None | 篇幅为 `custom` 时的目标页数 |

## 3. 用户对象 `user` 的可用字段/关系

`user` 为 duck-typed 对象（通常是 SQLAlchemy ORM 模型），模板内可访问：

- 标量字段：`name`、`phone`、`email`、`location`、`target_position`，均为字符串（可能为空）
- `hobbies`：字符串（部分数据可能没有，建议 `getattr(user, "hobbies", "")`）
- 关系集合（list，可能为空）：
  - `user.educations` — 教育经历
  - `user.skills` — 专业技能
  - `user.projects` — 项目经历
  - `user.internships` — 实习经历
  - `user.certificates` — 证书/获奖

各关系元素字段：

| 关系 | 元素字段 |
| --- | --- |
| education | `school`、`major`、`degree`、`start_date`、`end_date`、`courses`、`gpa`、`rank` |
| skill | `name`、`category`、`proficiency` |
| project | `title`、`role`、`tech_stack`、`start_date`、`end_date`、`description`、`result` |
| internship | `company`、`position`、`start_date`、`end_date`、`description`、`achievement` |
| certificate | `name`、`date` |

> 模板应通过 `_merge_sections(user, fabricated)` 拿到归一化后的四大列表：
> `projects, internships, works, others`（分别对应项目/实习/工作/其他经历），
> 其中合并了杜撰经历。工作/其他经历目前仅来源于杜撰。

## 4. 杜撰经历 `fabricated` 字段

每个元素为 dict，键：`type`（`project` / `internship` / `work` / `other`）、`title`、`role`、`tech_stack`、`start_date`、`end_date`、`description`、`result`。

`_merge_sections` 会把它们合并进对应列表：
- `project` → `projects`（字段与项目经历一致，`tech_stack` 可用）
- `internship` → `internships`（`title`→`company`、`role`→`position`、`result`→`achievement`）
- `work` → `works`（同上）
- `other` → `others`（同上）

## 5. 可复用工具函数（`resume_generator.py` 内）

| 函数 | 用途 |
| --- | --- |
| `_new_doc()` | 新建 Document（已设 A4 与页边距） |
| `_save_docx(doc, user, out_dir)` | 保存并返回文件路径 |
| `_merge_sections(user, fabricated)` | 返回 `(projects, internships, works, others)` |
| `_enabled(sections, key)` | 判断某模块是否应包含 |
| `_add_para(container)` | 取容器中的可写段落（Document / 表格单元格通用） |
| `_set_run(run, size, bold, color, italic)` | 设置 run 字体（含中英文字体） |
| `_add_rich_runs(p, text, size, color, bold)` | 渲染带 `**重点**` 标记的文本 |
| `_heading(container, text)` | 主栏小标题（蓝色 + 下边框） |
| `_side_heading(container, text)` | 侧边栏小标题 |
| `_entry_head(container, left, right, left_bold, tab_cm)` | 左侧加粗 + 右侧时间右对齐的一行 |
| `_bullet(container, text, size, color)` | 圆点条目（支持 `**` 标记） |
| `_tech_line(container, text)` | 「技术栈」行 |
| `_skill_cell(p, name, proficiency)` | 单个技能：名称 + 进度条 + 熟练度描述词 |
| `_skill_row(container, skills)` | 技能条目（每行可并列两个） |
| `_skill_lines(container, skills)` | 技能条目（每行一个，窄栏用） |
| `_skill_groups(user, skills_curated)` | 返回 `[(分类, [(名称, 熟练度)])]` |
| `_rule(container, color, sz)` | 分隔线 |
| `_side_info(container, label, value)` | 侧边栏「标签 + 值」一行 |
| `_cell_shading(cell, color)` | 单元格底纹（双栏侧边栏用） |
| `_no_table_borders(table)` | 去掉表格边框（双栏用） |

颜色常量：`PRIMARY`（主蓝）、`ACCENT`（强调蓝）、`GRAY`（灰）、`DARK`（正文深色）。

## 6. 强调标记约定

AI 生成的无格式正文（个人简介、自我评价、杜撰经历的 `description` / `result`）中，
需要加粗高亮的部分用 `**内容**` 包裹，例如 `**响应时间缩短 40%**`。

模板渲染时不要自己写正则去识别量化数字，统一调用 `_add_rich_runs` 解析 `**...**` 并渲染为蓝色加粗（`ACCENT`）。

## 7. 版式约定

- 核心量化信息 / 重要信息用蓝色加粗高亮（通过 `**` 标记）。
- 专业技能用进度条（`_skill_cell`）+ 熟练度描述词展示，不要把技能作为纯文本罗列。
- 自我评价固定置于简历最下方。
- 模块是否渲染，需通过 `_enabled(sections, key)` 判断，尊重用户勾选。

模块 key 取值：`summary`（个人简介）、`education`（教育背景）、`skills`（专业技能）、`internships`（实习经历）、`work`（工作经历）、`other`（其他经历）、`projects`（项目经历）、`certificates`（证书/获奖）、`self_evaluation`（自我评价）。

## 8. 完整示例

```python
def _render_my_template(user, jd_summary, personal_summary, self_evaluation, out_dir,
                        target_position="", sections=None, fabricated=None,
                        skills_curated=None, expected_salary="", include_salary=True,
                        length="fresh", custom_pages=None) -> str:
    def enabled(key):
        return _enabled(sections, key)

    projects, internships, works, others = _merge_sections(user, fabricated)
    doc = _new_doc()

    # 头部
    p = doc.add_paragraph()
    r = p.add_run(user.name or "姓名")
    _set_run(r, size=20, bold=True, color=PRIMARY)

    # 个人简介（含 ** 标记解析）
    if enabled("summary") and personal_summary:
        _heading(doc, "个人简介")
        p = doc.add_paragraph()
        _add_rich_runs(p, personal_summary, size=10)

    # ... 其余模块 ...

    return _save_docx(doc, user, out_dir)
```

登记：

```python
TEMPLATES = {
    "classic":      {"label": "简洁单栏", "render": _render_classic},
    "split":        {"label": "双栏",     "render": _render_split},
    "my_template":  {"label": "我的模板", "render": _render_my_template},
}
```

登记后，前端模板选择器会自动出现该模板，`POST /resumes/{id}/rebuild` 也会自动放行。
